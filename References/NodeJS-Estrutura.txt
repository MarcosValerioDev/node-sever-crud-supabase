Arquitura dirigida a:
- Alta escalabilidade
- Baixo acoplamento
- Alta coesão
- Facilidade de testes
- Facilidade de onboarding
- Padronização rigorosa de nomenclatura
- Preparada para crescer sem virar monolito bagunçado

BASE:
- Node.js + Express
- Arquitetura em Camadas + Clean Architecture
- Separação por Domínio (feature-first)
- SOLID
- Princípio da Inversão de Dependência
- Repository Pattern
- Service Layer Pattern
- DTO Pattern
- Factory Pattern
- Centralização de erros

ARQUITETURA
Camada          - Responsabilidade
Controller      - Lida com HTTP
Service         - Regras de negócio
Repository      - Acesso a dados
Domain          - Entidades e contratos
Infrastructure  - Implementações técnicas
Shared          - Código reutilizável

NOMENCLATURA
<feature>.<tipo>.ts
Ex:
user.controller.ts
user.service.ts

Classes sempre PascalCase
Ex:
UserController
UserService

Variáveis sempre CamelCase
Ex:
userRepository
createUserDto

Constants sempre UPPER_SNAKE_CASE
MAX_LOGIN_ATTEMPTS
DEFAULT_PAGE_SIZE
JWT_SECRET

FLUXO DE EXECUÇÃO
Route → Controller → Service → Repository → Database

Controller NUNCA acessa banco.
Service NUNCA conhece Express.
Repository NUNCA conhece HTTP.
